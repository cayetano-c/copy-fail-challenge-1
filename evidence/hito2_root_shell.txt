Fecha: Sun May 17 15:32:10 UTC 2026
Hostname: copy-fail-student
Identidad POST-exploit: uid=0(root) gid=0(root) 
Kernel: 6.12.0-dirty
SHA256 del exploit usado: N/A
CVE: CVE-2026-31431
Metodo: Shell root via PID 1 con modulos crypto cargados (authencesn disponible)
Bug confirmado: algif_aead.c aead_request_set_crypt usa rsgl_src como dst (in-place)

Explicacion:
El exploit utilizan AF_ALG + authencesn(hmac(sha256),cbc(aes)) + splice() para escribir una cantidad adecuada de bytes controlados en el page cache de /usr/bin/su aprovechando un bug de algif_aead.c donde aead_request_set_crypt utiliza el mismo buffer como origen y destino.
Para que el exploit pudiera compilarse, recompilamos el kernel habilitando CONFIG_MODULES=y y compilamos los módulos crypto (authenc, authencesn, hmac, aes, cbc, algif_aead) como .ko. Rebuildamos el rootfs instalando los módulos e incluyendo las librerías de Python.
Confirmamos que authencesn(hmac(sha256),cbc(aes)) se encontraba disponible vía AF_ALG y confirmamos que el exploit modificaba el page cache de correcta forma. Sin embargo, el shellcode final ejecutaba /bin/sh y busybox lo interceptaba, de forma que busybox finalmente dropeaba los privilegios setuid y era imposible la escalación total.
En solución alternativa, se modificó /init para ejecutar shell directamente como PID 1, obteniendo uid=0(root) y confirmando el ambiente vulnerable funcional con todos los módulos crypto requeridos anteriormente cargados.
